# QuietDesk：Codex 多 agent 原型开发提示词包

本包包含工程提示词、项目规则、完整产品规格和验收矩阵，不包含已经实现的桌面程序，也不包含已通过测试的声明。

## 使用
将本目录内容放入一个新的项目文件夹，例如 `D:\Projects\QuietDesk`；已有项目不要直接覆盖同名文件，应先让 Codex 阅读并合并。推荐让 Codex 在用户实际 Windows 本地工作目录操作，保留正常权限保护。安装依赖或需要额外能力时按明确授权处理，不使用全局关闭沙箱来解决问题。

在 Codex 打开该项目，发送：

```text
请阅读并执行 prompts/00-bootstrap.md。本轮只完成该文件指定的阶段，遵守 AGENTS.md。请实际使用当前可用的子 agent 能力，并如实报告不能执行的检查。
```

之后每轮将文件名按顺序替换为 01 到 07。每轮看完真实交付和问题后再发下一轮；某阶段失败先使用 `prompts/REPAIR.md`，新会话或中断恢复使用 `prompts/RESUME.md`。不用每次重新粘贴全部背景，项目文件承担持久上下文。

也可直接逐个复制 prompts 下文件的内容。`00-bootstrap.md` 包含完整的最小背景，适合从空目录开始；随包的 PRODUCT 与 ACCEPTANCE 提供更完整的细节，建议一并保留。

## 阶段
| 阶段 | 内容 | 主要检查 |
| --- | --- | --- |
| 0 | 环境、持久规格、分工、验收 | 真正具备哪些能力，而不是假定支持 |
| 1 | Windows 桌面宿主技术原型 | Win+D、覆盖、焦点、连续缩放 |
| 2 | 脚手架、类型/IPC、SQLite 烟雾测试 | 真实 Electron 进程读写持久化 |
| 3 | 数据层与 UI 有边界地并行实现 | 真实数据贯通，不是静态网页 |
| 4 | 快捷捕获与 Markdown | 中文 IME、草稿、失败保留、幂等提交 |
| 5 | Daily Log 与历史 | 跨天事实、补生成、删除传播 |
| 6 | 加固、Windows 打包与文档 | 脱离开发服务器，发布产物可运行 |
| 7 | 独立审查与最小修复 | 需求—实现—证据完整追踪 |

## 多 agent 的用法
角色是委派职责，不是需要另建的模型平台。当前官方文档支持向 Codex 明确请求子 agent；实际是否可用以本机客户端和账户/权限为准。先用内置委派，不默认配置额外 agent 服务、不硬编码模型名称或过时的功能开关。

Lead 是唯一集成者；Desktop、Data、UI、QA 按阶段启用，最多同时 3 个子 agent。读分析、审查容易并行，代码写入必须明确文件所有权。独立工作树可用于大量并行写入，但不能代替接口对齐、数据库隔离和最终集成测试。

## 重要门槛
桌面宿主是核心能力，不是装饰。它没有通过时，允许继续验证业务和 UI，但只能叫“开发预览”；不能将普通无边框窗口包装为完成的桌面组件。

跨天、删除与草稿是数据可靠性问题，必须用真实数据库及可注入时钟测试。视觉截图应实际渲染和检查，不能仅靠代码审查宣称符合要求。Windows Shell/IME/多屏人工项没有测试就是 NOT_RUN。

包内的 npm 脚本名是要求 Codex 创建的项目约定，不是 Codex 内置命令。在脚手架建立之前直接运行并不保证存在。

## 文件导航
- `AGENTS.md`：短期会话之外仍然有效的协作规则。
- `docs/PRODUCT.md`：完整产品语义与边界。
- `docs/ACCEPTANCE.md`：28 项验收情境，初始均未执行。
- `prompts/00-07*.md`：依次发送的阶段提示词。
- `prompts/RESUME.md` / `prompts/REPAIR.md`：恢复与故障纠偏。
- `docs/SOURCES.md`：已核查的官方平台资料。

ARCHITECTURE、CONTRACTS、PROGRESS、DESKTOP-SPIKE、RELEASE-CHECKLIST 等实施文档由 Codex 在对应阶段依据实际代码创建，包内不伪造这些结果。
